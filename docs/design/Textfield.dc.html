Textfield

Single-line text input: nickname, email, password. A visible label sits above the field, the field sits one step off the surface it is on, and there is no border. The search pill in the planner is the one variant.

  2. Counter optional, right of the label, 14px muted, current/max. Use it when the field has a max length.
  3. Field height 48px, radius --r-input (16px), padding 0 16px, text 16px. No border.
  4. Helper or error 13px below the field, gap 8px. Errors add an icon and say how to fix it.

Email and password: rules

  • Email attributes: type="email", inputmode="email", autocomplete="email", autocapitalize="none", spellcheck="false". Placeholder is an example address, never "Enter your email".
  • Email filled: text --ink, 16px, one line, ellipsis at the end when long. A clear button appears at the right edge only while there is text: 44x44, pill, icon X 18px stroke 2.4 in --ink-2; hover --row-hover and icon --ink; aria-label="Clear email". It empties the field and returns focus to it. The input has padding-right: 56px so text never runs under the button. No clear button on password fields.
  • Email validation: on blur and on submit, not while typing, and never before the first blur. Empty: "Enter your email." Malformed: "Use an address like name@example.com." Error clears as soon as the value becomes valid. Do not trim silently: trim whitespace on submit only. No green "valid" state; a valid field looks like a normal filled field.
  • Email in a profile: an email that cannot change is disabled (--disabled, text --ink-2) with helper "Email cannot be changed here." When it can change, the submit button stays disabled until the value is different and valid.
  • Password attributes: type="password" and autocomplete="current-password" to log in or confirm identity, new-password to create or change. Always autocapitalize="none", spellcheck="false". Never block paste or password managers, never autocomplete="off". Placeholder empty.
  • Show / hide toggle (the eye): 44x44 button, pill, inside the field at top:2px; right:2px; the input has padding-right: 56px. Icon Lucide eye (password hidden) or eye-off (password visible), 20px, stroke 2.2, --ink-2; hover background --row-hover and icon --ink; active scale(.94); focus outline: var(--focus) offset 0. The icon shows the current state of the field, the button states the action.
  • Toggle accessibility: aria-label="Show password" stays constant, aria-pressed switches true or false, aria-controls points at the input. Switching only changes type between password and text: keep the value, the caret position and the focus. Tab order: field, then toggle, then recovery link.
  • Visible state resets: the password hides again after a successful submit, when the dialog closes and when the page is left. It stays visible while the user moves between fields.
  • Log-in password: label on the left, "Forgot password?" link on the right of the label row (13px, 600, --accent-text, underline on hover). No rules, no counter, no strength. Error is generic and does not say which of email or password is wrong: "Email or password is incorrect."
  • New password: the rules are always visible under the field as a list (13px). Each item has an icon and text, never color alone: not met is a dash in --ink-2, met is a check in --ink with a visually hidden "Met" or "Not met" for screen readers. Rules: at least 8 characters, a letter, a number. The field shows no error while typing; the list is the feedback. On submit with unmet rules, the field gets the error tint and the message "Use at least 8 characters with a letter and a number."
  • Confirm password: no toggle of its own, it follows the field above. Validate on blur: "Passwords do not match." Re-check when the first field changes. autocomplete="new-password" on both.
  • Caps Lock: while a password field has focus and Caps Lock is on, show "Caps Lock is on." in 13px with an alert icon under the field (role="status"). It disappears when Caps Lock is off or on blur.
  • Error look: same as the base field: background tinted from --accent at 12%, message in --ink 13px with an alert icon, aria-invalid="true" and aria-describedby. The toggle and clear button keep their normal colors on the tint.
  • Submit: pill 48px, disabled until the form is valid; Enter submits from any field. While sending, spinner inside the button and fields stay editable-looking but read-only. Messages from the server go in the helper line of the field they refer to, and focus moves to it.
  • Dark theme and mobile: same tokens swap automatically. The toggle and clear buttons stay 44px on mobile; the keyboard is the email keyboard for email, and the first-letter capitalization is off.

Specification

  • Background: one step off the surface behind it. On --surface (cards, popups) the field is --bg; on --bg (a panel inside a popup) the field is --surface. Never the same color as its container, never --row on --bg.
  • Size: 48px high, radius 16px, padding 0 16px, text 16px (never smaller, so iOS does not zoom). Full width of its column; max 480px in forms. Search pill: 56px, radius pill.
  • No border. Hover: inset 2px ring --row-hover. Focus: outline: var(--focus), offset 2px, via :focus-visible. Pressing or typing does not change the surface.
  • Filled: text --ink. Empty: placeholder in --ink-2, an example of the value, never an instruction that replaces the label.
  • Error: background tinted from --accent at 12% over the base (color-mix), message below in --ink 13px with an alert icon, aria-invalid="true" and aria-describedby on the field. The message says what to do ("Use at least 3 characters"), never only "Invalid". Validate on blur or submit, not on the first keystroke.
  • Disabled: background --disabled, text --ink-2, cursor:not-allowed. Prefer a disabled submit button over a disabled field; a field is disabled only when the value cannot change.
  • Counter: shown when maxlength is set: 14px --ink-2 tabular numbers, right of the label. Nickname max 30.
  • Types: text with autocomplete="nickname", email with autocomplete="email", password with current-password or new-password. Password helper states the rule ("At least 8 characters"). A show or hide toggle is a 44x44 button inside the right edge, with aria-pressed.
  • Forms: label to field gap 8px, field to field gap 20px, group to submit 24px. Submit is a pill, 48px, disabled until the form is valid; Enter submits.
  • Dark theme: same tokens swap: field --bg on --surface, hover ring --row-hover, focus ring stays --accent on the dialog and --highlight on dark headers.
  • Mobile: same height and text size. Full width, keyboard type matches the field type, labels never turn into floating placeholders.
